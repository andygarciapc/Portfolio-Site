Game Mods

The Challenge

I identified unmet player needs in Mount and Blade II: Bannerlord and Worldbox—features that the community wanted but weren't supported by the base games. The challenge was figuring out how to implement these features without access to source code or official modding documentation.

Screenshot: Mod feature in action (1920x1080 recommended)

One of the gameplay modifications in action

The Approach

Using dnSpy to reverse-engineer the closed-source game systems, I was able to understand how the game's internal mechanics worked. This allowed me to find extension points and hooks where I could inject custom functionality without breaking existing behavior.

  • Analyzed game assemblies using dnSpy to understand internal structures
  • Identified stable extension points that wouldn't break between game updates
  • Designed modular architecture to make mods easy to maintain and update
  • Implemented data-driven configs so players could customize behavior without code changes

Key insight: By making mods data-driven rather than hardcoded, I could rapidly iterate on features and allow users to customize their experience without needing to recompile the mod.

Technical Highlights

Beyond just adding features, I had to solve real engineering problems:

  • Debugged race conditions that caused crashes during multiplayer sessions
  • Fixed memory leaks that appeared over long play sessions
  • Handled save/load edge cases where mod data needed to persist correctly
  • Maintained compatibility across multiple game versions and updates

Results

The mods were well-received by the community, accumulating over 20,000 downloads combined. More importantly, I learned how to ship real software that real people use—handling bug reports, maintaining backwards compatibility, and iterating based on user feedback.
